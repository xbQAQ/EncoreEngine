# FBX 静态模型导入

统一入口 `render::ImportSceneFile(path)` 按扩展名分派 `.fbx`、`.gltf` 和 `.glb`，不区分扩展名大小写。`ImportFbx` 和 `ImportGltf` 仍可独立调用。主文件和外部纹理使用原生 `std::filesystem::path` 读取，支持中文路径。

FBX 解析使用官方 [ufbx](https://ufbx.github.io/) 的固定版本 [v0.23.1](https://github.com/ufbx/ufbx/tree/v0.23.1)，提交 `26a482ae66871d7de36eb722aa060bce95bce274`。下载归档的 SHA256 为 `3e5d8219f5b634fd374949808206eba1a1da49b2b2e3ee31ff0bd228c0abd469`。项目不手写 FBX 文本或二进制解析器，不要求安装 Autodesk FBX SDK，也不依赖 Blender 进程。

## Blender 导出

1. 选择需要的网格，通过 `File > Export > FBX` 导出。保留网格法线、UV 和材质，使用第一个 UV 集。
2. 关闭动画导出。骨骼和形态键可以保留，但导入器只通过 ufbx 求值器烘焙文件默认姿态及当前形态权重，运行时不保留骨骼、形态键或动画播放系统。
3. 使用 Principled BSDF 的基础色、金属度、粗糙度、法线、自发光和透明度输入。程序纹理、复杂节点混合、位移及高度凹凸应先烘焙。
4. 纹理使用 PNG/JPEG。可选择嵌入 FBX，或将图片与模型一起搬移并保留相对路径；不要仅交付 `.blend` 或未复制图片的 FBX。
5. 透明裁切按覆盖率阈值处理。玻璃应使用物理透射参数；本导入器不提供排序透明混合。

编辑器的“导入模型”入口和内容浏览器可以选择 FBX，结果追加到当前场景。每个文件成为一个以文件名命名的完整模型对象，内部节点的材质分组保留在该模型的表面绑定中。选择或变换模型时，所有表面作为整体操作；保存世界后保留各表面材质、纹理和脚本。完整编辑行为见 [Blender 静态场景导入](BlenderImport.md)。

```powershell
.\EncoreEngine.exe --scene .\模型\角色.fbx
```

## 几何与材质

| 数据 | 转换行为 |
|---|---|
| 文件格式 | 官方解析器支持的 ASCII 与二进制 FBX；主文件读取上限为 4 GiB |
| 坐标 | 根据 FBX 坐标轴和单位统一为米制、右手 Y 向上空间 |
| 节点 | 祖先变换、节点实例和几何专用变换均烘焙到世界空间；镜像同步翻转三角形绕序 |
| 表面 | 官方多边形三角化；按节点实际绑定的材质输出连续表面范围 |
| 属性 | 平滑法线、第一 UV 集、作者切线；缺失法线由 ufbx 生成，缺失切线由 UV 推导 |
| 变形 | 默认骨骼姿态和当前形态权重烘焙；已在世界空间的求值结果不重复应用节点变换 |
| 材质 | ufbx PBR 映射及传统 Phong/Lambert；Phong 高光指数近似映射粗糙度 |
| 常数 | 线性基础色、自发光、金属度、粗糙度、透射、IOR、清漆、各向异性和绒毛等可表达参数 |
| 图像 | 内嵌字节或外部相对路径的 PNG/JPEG，WIC 解码为自有 RGBA8 像素 |
| 采样 | 第一 UV 集、平移/旋转/缩放、Repeat/Clamp；UV 的 V 方向与切线手性同步转换 |
| 材质关联 | 原始节点材质槽写入每片三角形，完整模型对象保存连续表面绑定；无材质表面使用独立默认槽 |

基础色 RGB 和自发光 RGB 在着色器中按 sRGB 解释，法线、粗糙度、金属度、透射和覆盖率按线性数据解释。CPU 不统一转换图片 Gamma；同一来源图片的不同颜色空间视图共享像素字节。

独立的粗糙度/金属度图片打包到现有 G/B 契约，基础色/覆盖率打包到 RGBA。参与打包的图像必须使用相同 UV 变换和包裹方式，分辨率不同则按最大宽高最近邻重采样。相同来源只解码一次，相同打包输入也只生成一份像素数据。Blender 将同一图片的 Alpha 再连接透明度时，直接保留原 RGBA，避免透明度平方和按材质复制大图。

运行时材质为 Disney 参数化，不能精确重现任意 DCC 材质网络。透明度贴图使用二值裁切，部分覆盖常数会明确拒绝。FBX 不带 glTF 的完整材质扩展契约；复杂表面建议先烘焙并在编辑器中检查。

## 明确边界

- 暂不导入 FBX 摄像机和灯光；编辑器提供场景默认相机和灯光，可在导入后编辑。
- 动画曲线、外部顶点缓存、非表面原语、带孔多边形、顶点颜色、第一 UV 集之外的贴图、分层/程序/着色器纹理、二维剪切 UV 变换，以及不能映射到运行时槽的高级参数贴图会明确拒绝。
- 高度凹凸和位移要求先烘焙为切线空间法线。TGA、DDS、KTX、EXR 等图像要求先转换为 PNG/JPEG；不能仅更改文件后缀。
- 外部图片依次尝试来源相对路径、记录的绝对路径和模型同目录文件名。缺失图片明确失败，不生成占位色，不下载远端资源。
- 单张图片每边最多 16384 像素；解析器临时和结果分配各限制为 1 GiB；IOR 支持 1 到 4；几何和材质需在现有精确浮点索引容量内。
- 截断文件、无效索引导致的解析失败、奇异变换、退化三角形、非法数值和缺失图片不会发布部分场景。ufbx 自身会把越界面材质索引归零，严格模式也保留该官方兼容行为；导入器会保留全部表面并验证最终 GPU 材质引用。

## 自动验证

`tests/fixtures/two_materials.fbx` 是本项目构造并维护的合法 ASCII FBX 7400：两个四边形、双材质、父节点及几何专用变换、法线/UV/切线，以及内嵌双色 PNG。它不冒充 Blender 导出产物，也不需要外部模型许可证。`invalid.fbx` 是刻意截断的反例。

```powershell
cmake --build build --config Release --target fbx_import_tests asset_import_tests
ctest --test-dir build -C Release --output-on-failure -R "^(fbx_import|asset_import)$"
.\build\Release\fbx_import_tests.exe --inspect .\模型\角色.fbx
```

测试实际验证官方解析器三角化、世界变换、材质分组、PNG 颜色/Alpha、共享像素、Blender 同图透明度、外部图片、中文及大写扩展名路径、镜像绕序、奇异变换、截断输入、官方材质索引修复，以及导入对象的世界文档保存和恢复。`--inspect` 走相同正式入口，输出三角形、表面、材质、视图、唯一图片、像素数量和米制包围盒，便于核对真实模型。
